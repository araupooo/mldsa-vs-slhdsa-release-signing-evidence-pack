Headline result

PASS — both schemes sign and verify real release artifacts with all 7 parameter sets: 56/56 correctness checks pass. ML-DSA-65 is the general-purpose default (142 µs sign, 3,309-byte signature, category 3). SLH-DSA-128s is the hash-only hedge (720 ms sign, 7,856-byte signature, category 1) — 5,000x slower to sign, but its security rests only on hash functions. Within SLH-DSA, the f variant signs 21x faster than the s variant (34.6 ms vs 720.2 ms) at 2.2x the signature size. Fresh-clone re-runs of the full suite agree within a few percent (see Table 5).

Limitations

  • L1 — Single build configuration: only the optimized liboqs build was measured; no reference (generic) build.
  • L2 — Timing noise: single shared VM; medians are the robust comparison.
  • L3 — Randomized signatures: signature bytes differ between runs; tests assert on outcomes and lengths only.
  • L4 — Canonicalization subset: sorted JSON keys, no whitespace — not full JCS (RFC 8785).
  • L5 — Transparency log is local: single operator, no auditors, gossip, or signed tree heads.
  • L6 — Hardware-backed signing not tested: no HSM available; documented from vendor/docs sources only.
  • L7 — Parameter-set coverage: SHA-2 s/f sets only; SHAKE and prehash variants not measured.
  • L8 — Single artifact shape: one small tarball + two synthetic large files.
  • L9 — Revocation enforcement is procedural: no revocation list in the harness.
